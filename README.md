# Bot Detection Challenge

Детекция ботов на Авито по событиям внутри суточного окна.
Метрика: **Precision при Recall ≥ 70%** (`precision_at_recall` из `metric.py`).

## Задача

По событиям cookie_id за суточное окно предсказать вероятность, что кука принадлежит сервису автоматизированного сбора данных (target=1), а не человеку (target=0).

## Данные

- `train.csv` — 11 091 кука с таргетом (доля ботов **8.11%**).
- `test.csv` — 4 909 кук без таргета.
- `events.csv.gz` — 328 905 событий.
- Окно наблюдения — сутки, у каждой куки своё (`window_start_ts` → `window_end_ts`).

**Данные не приложены.** Положите `train.csv`, `test.csv`, `events.csv.gz` в `data/` перед запуском.

## Подход

### Валидация
- **Time-based холд-аут**: обучение на `window_start_ts < 2026-04-17`, валидация на более поздних.
- **TimeSeriesSplit (5 фолдов)** — проверка стабильности.
- Случайный сплит не использовался — test лежит позже train, иначе утечка будущего.

### Обработка данных
- **Окно:** события фильтруются строго по `[window_start_ts, window_end_ts)`.
- **Дубликаты:** в `events` найдено 4 863 полных дубля (1.5%) — удалены через `drop_duplicates()`. Эффект: LightGBM вырос с 0.4302 до 0.4807 (+0.05).
- **Пропуски:** доли пропусков по 7 полям используются как признаки (пропуск — это сигнал, а не баг). Например, отсутствие `pointer_x/y` или `search_query` само по себе отличает ботов.
- **Категориальные:** `platform` приведён к нижнему регистру и замаплен в 4 категории (web/desktop/android/ios). `user_agent` — эвристический флаг `ua_suspicious` (regex на bot/spider/crawler), без полного парсинга. `event_name` — доли и счётчики по каждому типу.

### Признаки (72)

**Базовые (64):**
- объём и разнообразие: n_events, nunique по item/category/location/seller/query/platform/UA;
- доли пропусков по 7 полям;
- доли и счётчики по каждому типу события;
- интервалы между событиями: mean/median/std/min/max/p25/p75, `dt_cv` (ровность ритма), `short_interval_share`, `long_pause_count`;
- активность по времени суток (night/morning/day/evening);
- платформенные доли;
- возраст куки на момент начала окна (`cookie_age_sec`);
- длина поискового запроса, `eid_ratio` топ-5.

**Кандидаты (8), отобранные по положительному delta:**
- `p01_interval_sec`, `p05_interval_sec`, `share_under_0_5s`;
- `phone_show_ratio`, `chat_open_ratio`, `has_any_contact`;
- `unique_search_pages`, `items_per_event`.

### Модели
- **Baseline:** LogisticRegression (StandardScaler, class_weight='balanced').
- **Основная:** LightGBM (learning_rate=0.03, num_leaves=63, early_stopping=150, random_state=42).

## Результаты

| Эксперимент | Фич | P@R0.7 |
|---|---|---|
| Константа (доля ботов) | — | 0.0811 |
| LogReg (baseline) | 64 | 0.2924 |
| LightGBM, все фичи (v1) | 64 | 0.4807 |
| LightGBM, top-30 по важности | 30 | 0.4609 |
| **LightGBM, все + кандидаты (v2)** | **72** | **0.5385** |

**TimeSeriesSplit (5 фолдов, финальный набор):**
- Среднее P@R0.7: **0.4733**
- Std: 0.0533
- Min / Max: 0.3993 / 0.5354

Холд-аут (0.54) выше среднего CV (0.47) — нормально: холд-аут один срез, CV усредняет 5 периодов. **Честная оценка для скрытого теста: ~0.47–0.50.**

## Отбор фич

- **Отсев по feature importance не помог**: top-30 (0.4609) хуже, чем все 64 (0.4807). Слабые фичи вносят вклад в ансамблевом смысле → оставлены все.
- **Поштучный тест кандидатов**: из 14 оставлены 8 с положительным delta. Удалены `p10`, `p90`, `contact_ratio`, `message_sent_ratio`, `time_to_first_contact_sec` — после удаления дублей их delta стала отрицательной (эффект был артефактом дублей).
- **Исключённые фичи:** `captcha_ratio` — константа 0, события `captcha_shown` не попадают в окно.

## Ограничения

- Разрыв холд-аут vs CV: **0.54 vs 0.47**. Ориентир для теста — **0.47–0.50**.
- **CV std = 0.053** — модель нестабильна между периодами (мало данных в ранних фолдах).
- **Разметка покрывает только известные сервисы сбора данных** — другие типы автоматизации могут не детектироваться.
- **`user_agent`** используется эвристически, без полного парсинга.

## Направления дальнейшей работы

- Тюнинг LightGBM (`num_leaves`, `learning_rate`, `min_child_samples`) — потенциально +0.01–0.03.
- Дополнительные фичи: интервалы только между `item_view`, `n_unique_queries_per_hour`, `photo_swipes_per_item`.
- Полный парсинг `user_agent` (устройство, ОС, версия).
- Стабилизация CV: усреднение по 3 seed'ам.
